    NUnit Framework

    NUnit is a popular unit-testing framework for .NET.

    Features of NUnit Framework

    • Multiple Asserts: Assert.Multiple() allows raising multiple assertions in a single test.
    • Parallel Execution: Supports parallelism at test method and test fixture levels.
    • Test-Driven Development (TDD): Facilitates TDD practices.
    • Author Attribution: Enables multiple authors to be attributed to the code.
    • Annotations: Uses annotations to speed up test development and execution.

    Execution Flow of NUnit Test

    A basic process flow of a Selenium Testing program with NUnit involves the following steps:

    Annotations in NUnit

    • TestFixture:
      • A class-level attribute indicating that the class contains NUnit test methods.
      • Can only be placed on classes, not methods.
      • Supports parameterized TestFixtures via constructors.
      • If no arguments are provided, the class must have a default constructor.
      • Multiple TestFixture attributes can be used on a single class.
      • TestFixture attribute can be inherited.
    • TestCase:
      • Marks a method as a test method.
      • Passes arguments/parameters to the test method.
      • TestCase attribute properties:
        • Parameterized: [TestCase(20)] - Passes arguments/parameters to the method.
        • ExpectedResult: [TestCase(parameter, ExpectedResult = false)] - Validates the return type of the method.
        • Author: [TestCase(Author = "Abhishek")] - Assigns the author of the test case.

    NUnit Assert Examples

    Assert methods compare the actual result with the expected result. If they match, the test case passes; otherwise, it fails.

    Constraint Model

    NUnit provides a constraint model using the That method to improve test method readability. The That method applies constraints to the actual value.

    Helper Classes

    Helper classes provide constraints for assertions:

    • Is
    • Has
    • Contains
    • Does
    • Throws

    Important Points

    • The Keys class provides keyboard keys like RETURN, F1, ALT, etc.
      • Example (Python): from selenium.webdriver.common.keys import Keys

    Page Object Model (POM) in Selenium C#

    POM is a design pattern used to improve the maintainability of Selenium test code.

    Advantages

    • Separation of test code and page-specific code (locators, layout).
    • Centralized repository for page services/operations.

    Example of Login using POM and without POM

    Login Feature without POM

    public class Login
{
    public void testLogin()
    {
        // Fill login data on sign-in page
        driver.findElement(By.name("user_name")).sendKeys("userName");
        driver.findElement(By.name("password")).sendKeys("my supersecret password");
        driver.findElement(By.name("sign-in")).click();

        // Verify h1 tag is "Hello userName" after login
        driver.findElement(By.tagName("h1")).isDisplayed();
        assertThat(driver.findElement(By.tagName("h1")).getText(), is ("Hello userName"));
    }
}
    Problems with this approach:
    • No separation between test methods and locators.
    • Locators are scattered across multiple tests.

    Login Feature with POM

    • Create a directory containing page classes/page objects.
    • Create another directory containing test scripts/actual code implementation.
    public class SignInPage
{
    protected WebDriver driver;
    private By usernameBy = By.name("user_name");
    private By passwordBy = By.name("password");
    private By signinBy = By.name("sign_in");

    public SignInPage(WebDriver driver)
    {
        this.driver = driver;
        if (!driver.getTitle().equals("Sign In Page"))
        {
            throw new IllegalStateException("This is not Sign In Page, current page is: " + driver.getCurrentUrl());
        }
    }

    public HomePage loginValidUser(string userName, string password)
    {
        driver.findElement(usernameBy).sendKeys(userName);
        driver.findElement(passwordBy).sendKeys(password);
        driver.findElement(signinBy).click();
        return new HomePage(driver);
    }
}

    Page Factory in Selenium C#

    • Page Factory is a design pattern that enhances POM.
    • It Initializes page class elements without FindElement.
    • It Uses @FindsBy annotation to find elements.
    • PageFactory.InitElements() must be use to initializes web elements.

    Example Pagefactory:

    using OpenQA.Selenium;
using SeleniumExtras.PageObjects;

public class LoginPage
{
    private readonly IWebDriver driver;

    public LoginPage(IWebDriver driver)
    {
        this.driver = driver;
        PageFactory.InitElements(driver, this);
    }

    [FindsBy(How = How.Id, Using = "username")]
    public IWebElement UsernameInput { get; set; }

    [FindsBy(How = How.Id, Using = "password")]
    public IWebElement PasswordInput { get; set; }

    [FindsBy(How = How.Id, Using = "loginButton")]
    public IWebElement LoginButton { get; set; }

    public void Login(string username, string password)
    {
        UsernameInput.SendKeys(username);
        PasswordInput.SendKeys(password);
        LoginButton.Click();
    }
}

    Data-Driven Testing in C#

    Data-driven testing involves running the same test multiple times with different sets of input data.

    Techniques for Data-Driven Testing

    1. NUnit Attributes and Parameterized Methods:

      • Using [TestCase()] attribute to provide parameters for test methods.

    2. Product Model:

      • When dealing with complex product details, using a product model as a parameter can simplify test data management.
      • Instead of passing individual parameters, pass a model object containing all relevant data.

    3. Random Data Generation using AutoFixture:

      • Install the AutoFixture.NUnit3 NuGet package.
      • Use the [AutoData] attribute to generate random data for test parameters.

    4. SpecFlow Scenario Outline:

      • Use SpecFlow's scenario outlines to supply data from feature files.

    5. External Data Files (CSV, Excel, etc.):

      • Read test data from external files like CSV or Excel.

    6. Passing Complete Models:

      • Create a model, assign values to its properties, and pass the model to the test method to create requests.

    7. Using appsettings.json:

      • Extract configuration data from appsettings.json files.

    Working with Config file (appsettings.json)

    Steps to read test settings from a configuration file:

    1. Create appsettings.json:

      • Create a JSON file named appsettings.json to store configuration data.

    2. Configure appsettings.json to Copy to Bin Directory:

      • Option 1 (Visual Studio):
        • Select the file in Solution Explorer.
        • Go to Properties.
        • Set "Copy to Output Directory" to "Copy always".

      • Option 2 (Project File):

        • Add the following configuration to your project file (.csproj):

        xml <ItemGroup> <None Update="appsettings.json"> <CopyToOutputDirectory>Always</CopyToOutputDirectory> </None> </ItemGroup>

    3. Create ConfigReader.cs:

      • Create a ConfigReader.cs file to read data from appsettings.json and map it to a model (e.g., TestSetting).

    4. Access Data:

      • Use the ConfigReader.ReadConfig() method to access the data.

      csharp TestSetting testSetting = ConfigReader.ReadConfig();

    Parallel Testing and Reporting in C#

    Parallelizable

    When running multiple tests in parallel, WebDriver instances can interfere with each other, leading to data mismatches. To prevent this, we use thread-safe WebDriver instances.

    • Thread Safety:

      • Initialize WebDriver using ThreadLocal<IWebDriver>: csharp public ThreadLocal<IWebDriver> driver = new ThreadLocal<IWebDriver>();
      • Access the WebDriver instance using driver.Value.

    • Parallelization Annotations:

      1. Parallel Data Sets within a Test Method:

        • [Parallelizable(ParallelScope.All)]
        • Place before the test method to run all data sets in parallel.

      2. Parallel Test Methods within a Class:

        • [Parallelizable(ParallelScope.Children)]
        • Place before the class to run all test methods in the class in parallel.

      3. Parallel Test Files within a Project:

        • [Parallelizable(ParallelScope.Self)]
        • Place before the class in each test file to run all test files in the project in parallel.

    Selenium Grid and Parallel Testing

    Selenium Grid allows running WebDriver scripts on remote machines to enable parallel testing and cross-browser testing.

    • Goals:

      • Run tests in parallel on multiple machines.
      • Test on different browser versions.
      • Enable cross-platform testing.

    • Setup:

      1. Prerequisites:

        • Java 11 or higher installed.
        • Browsers installed.
        • Browser drivers:
          • Selenium Manager (recommended): java -jar selenium-server-<version>.jar standalone --selenium-manager true
          • Manually installed and added to PATH.
        • Selenium Server JAR file (download from latest release).

      2. Start the Grid: bash java -jar selenium-server-<version>.jar standalone

      3. Point WebDriver Tests:

        • Configure WebDriver to connect to http://localhost:4444.

      4. (Optional) Check Grid Status:

        • Open http://localhost:4444 in a browser.

    • Configure WebDriver:

      ```csharp public IWebDriver GetRemoteWebDriver(BrowserType browserType) { IWebDriver driver;

      switch (browserType)
{
    case BrowserType.ChromeDriver:
        driver = new RemoteWebDriver(_testsetting.GridUri, new ChromeOptions());
        break;

    SpecFlow: Behavior-Driven Development for .NET

    What is SpecFlow?

    • SpecFlow is a Behavior-Driven Development (BDD) framework for .NET, similar to Cucumber.
    • It uses Gherkin, a plain-text language, which supports over 70 languages.
    • It is cross-platform, running on macOS, Linux, and Windows.
    • SpecFlow integrates with popular IDEs like Visual Studio, VS Code, and Rider.

    Why Use SpecFlow?

    • SpecFlow uses simple English language, enabling clear communication between QAs, developers, BAs, and POs.
    • It fosters a shared understanding across the team.
    • It aids in documenting the entire Software Development Life Cycle (SDLC).

    SpecFlow Ecosystem

    The SpecFlow ecosystem supports the entire SDLC, from requirements gathering to project delivery.

    Role Tool/Feature
    Business Analyst, Product Owner SpecFlow Online Gherkin Editor
    Developers, QA Leads, Automation Testers SpecFlow plugins for IDEs
    DevOps/QA/Developers Azure DevOps SpecFlow LivingDoc
    Client (Stakeholder) SpecFlow LivingDoc (offline/hosted)

    SpecFlow in the SDLC

    • Requirement Gathering:
      • Gherkin Language:
        • Purpose: Write requirements in plain English using the Given-When-Then format.
        • Benefit: Ensures all stakeholders understand the requirements.
      • Collaboration:
        • Tools: Integrates with Azure DevOps and Git.
        • Benefit: Facilitates collaboration between BAs, developers, and testers.
    • Development:
      • SpecFlow:
        • Integration: Works with Visual Studio and other .NET tools.
        • Functionality: Converts Gherkin scenarios into executable code.
      • SpecFlow+ Runner:
        • Purpose: Advanced test execution and reporting.
        • Benefit: Provides detailed insights and control over test runs.
    • Testing:
      • Automated Testing:
        • CI/CD Integration: Supports automated acceptance tests in CI/CD pipelines.
        • Benefit: Ensures consistent test execution.
      • SpecFlow+ LivingDoc:
        • Purpose: Generates living documentation from feature files.
        • Benefit: Keeps documentation up-to-date.
    • Project Delivery:
      • Continuous Feedback:
        • Tools: SpecFlow+ LivingDoc and SpecMap.
        • Benefit: Provides continuous feedback on requirements and tests.
      • Documentation:
        • LivingDoc: Keeps stakeholders informed with up-to-date documentation.
        • Benefit: Ensures the final product meets requirements.

    Creating Extent Report UI with Step Definitions

    Defining and Logging in Reports in hook files.

    [BeforeScenario()]
public void InitializeDriver()
{
    var feature = _extentReports.CreateTest<Feature>(_featureContext.FeatureInfo.Title);
    _scenario = feature.CreateNode<Scenario>(_scenarioContext.ScenarioInfo.Title);
}

[AfterStep]
public void AfterTestSteps()
{
    if (_scenarioContext.TestError == null)
    {
        switch (_scenarioContext.StepContext.StepInfo.StepDefinitionType)
        {
            case TechTalk.SpecFlow.Bindings.StepDefinitionType.Given:
                _scenario.CreateNode<Given>(_scenarioContext.StepContext.StepInfo.Text);
                break;
            case TechTalk.SpecFlow.Bindings.StepDefinitionType.When:
                _scenario.CreateNode<Given>(_scenarioContext.StepContext.StepInfo.Text);
                break;
            case TechTalk.SpecFlow.Bindings.StepDefinitionType.Then:
                _scenario.CreateNode<Given>(_scenarioContext.StepContext.StepInfo.Text);
                break;
        }
    }
    else
    {
        switch (_scenarioContext.StepContext.StepInfo.StepDefinitionType)
        {
            case TechTalk.SpecFlow.Bindings.StepDefinitionType.Given:
                _scenario.CreateNode<Given>(_scenarioContext.StepContext.StepInfo.Text).Fail();
                break;
            case TechTalk.SpecFlow.Bindings.StepDefinitionType.When:
                _scenario.CreateNode<Given>(_scenarioContext.StepContext.StepInfo.Text).Fail();
                break;
            case TechTalk.SpecFlow.Bindings.StepDefinitionType.Then:
                _scenario.CreateNode<Given>(_scenarioContext.StepContext.StepInfo.Text).Fail();
                break;
        }
    }

    JavaScriptExecutor in Selenium

    • JavaScriptExecutor allows executing JavaScript code in the browser context.
    • Useful for operations not directly supported by Selenium.
    • Provides two methods ExecuteScript and ExecuteAsyncScript.

    steps to use:

    1. Import the package: import org.openqa.selenium.JavascriptExecutor;
    2. Create a reference: JavascriptExecutor js = (JavascriptExecutor)driver;
    3. Call the method: js.executeScript(script, args);

    ExecuteScript

    Executes JavaScript in the current window or frame. Returns values of types: WebElement, List, String, Long, Boolean.

    using OpenQA.Selenium;
using OpenQA.Selenium.Chrome;

class Program
{
    static void Main()
    {
        IWebDriver driver = new ChromeDriver();
        driver.Navigate().GoToUrl("[https://example.com](https://example.com)");
        IJavaScriptExecutor js = (IJavaScriptExecutor)driver;

        IWebElement elementToScrollTo = driver.FindElement(By.Id("elementId"));
        js.ExecuteScript("arguments[0].scrollIntoView(true);", elementToScrollTo);

        js.ExecuteScript("arguments[0].style.backgroundColor = 'yellow';", elementToScrollTo);

        string title = (string)js.ExecuteScript("return document.title;");
        Console.WriteLine("Page Title: " + title);

        IWebElement button = driver.FindElement(By.Id("buttonId"));
        js.ExecuteScript("arguments[0].click();", button);

        IWebElement inputField = driver.FindElement(By.Id("inputFieldId"));
        js.ExecuteScript("arguments[0].value='New Value';", inputField);

        driver.Quit();
    }
}
