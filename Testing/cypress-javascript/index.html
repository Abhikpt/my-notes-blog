    Cypress Learning

    ✨ Overview

    • Cypress is a web UI automation tool for modern JavaScript applications (e.g., React, Angular, Vue).

    🔹 Features

    1. Time Travel – View DOM snapshots by hovering over each step.
    2. Debuggability – Debug in the same browser window without re-running.
    3. Automatic Waits – Cypress waits for DOM and elements automatically.
    4. Consistent Results – Runs yield consistent behavior.
    5. Auto Screenshots & Videos – Automatically captures on failure.
    6. Cross-Browser Testing – Runs on Chrome, Edge, Firefox, Electron.

    ❌ Limitations

    1. Cannot automate Windows or mobile native apps.
    2. Limited community support.
    3. Only JavaScript/TypeScript supported.
    4. Difficult file read/write operations.
    5. Limited 3rd-party reporting integration.

    🔄 Test Structure

    Test Format

    • Spec File (.cy.ts) → describe() block → it() blocks

    Sample

    describe("Home Page", () => {
  it("The h1 contains the correct text", () => {
    cy.visit("http://localhost:3000")
    cy.get("h1").should("contain", "Welcome")
  })
})

    Important Methods

    • describe("Test Suite Name", callback)
    • it("Test Case Description", callback)
    • .only() → Run specific test or suite
    • .eq(index) → Selects element by index from matched set

    📊 Assertions

    1. Implicit assertion

    • Should
    • Add
    cy.get("h1").should("contain", "Welcome").and("be.visible")
    • Chaining: should().should() or should().and()
    • Common matchers: eq, contain, include, have.length, have.value

    2. Explicit assertion

    BDD Style

    cy.get("h1").then(($el) => {
  expect($el.text()).to.equal("Welcome")
})
    • here return value from get is pass through funcation and compared inside function.

    TDD Style

    assert.equal(actual, expected)

    ⚙ Time Travel Debugging

    • Helps trace issues by inspecting past DOM states.

    1. Blank screen on hovering test steps

    Fix: Add testIsolation: false in cypress.config.ts

    import { defineConfig } from "cypress";

export default defineConfig({
  e2e: {
    setupNodeEvents(on, config) {},
    testIsolation: false,
  },
});

    ✨ Best Practices

    • Use data-cy attributes for selectors.
    • Keep reusable functions in commands.ts.
    • Add plugins in support/e2e.ts.
    • Use .only() and .skip() for selective execution.
    • Structure folders clearly: e2e/, fixtures/, support/.

    🧠 Cypress Architecture & Key Concepts

    Cypress vs Traditional Tools

    Feature Selenium/Protractor Cypress
    Execution Outside browser (via drivers) Inside browser
    Speed Slower (network hops) Very fast
    DOM Access Indirect via driver Direct
    Network Control Limited Full control, mock support
    Auto-Wait Manual Built-in
    Browser Support Wide Chrome, Firefox, Electron, Edge
    • Traditional tools use browser drivers and communicate over a network.
    • Cypress executes test code inside the browser, eliminating drivers and network latency.
    • Advantages: faster execution, direct DOM control, network interception, auto-waiting, real-time execution.

    Test Capabilities

    • Unit, Integration, and End-to-End (E2E) testing.
    • Fits multiple SDLC stages.

    Supported Browsers

    • Chrome, Firefox, Edge, Electron (default, lightweight Chromium).

    Cypress Components

    • Test Runner: UI for running/debugging tests, time-travel, live reload.
    • Dashboard Service: Optional cloud service for historical results, videos, error logs.

    🛠️ Cypress Installation & Setup

    1. Install Node.js: Download from official site.
      • Verify: node -v, npm -v
    2. Set NODE_HOME (Windows): Add Node.js path to environment variables.
    3. Install VS Code: Recommended editor.
    4. Create Project Folder: mkdir cypress-automation && cd cypress-automation
    5. Initialize npm Project: npm init -y
    6. Install Cypress: npm install cypress --save-dev
    7. Run Cypress: npx cypress open (creates /cypress folder structure)
    8. Share Setup: Commit package.json and package-lock.json; teammates run npm install.

    🧪 Cypress Test Runner & CLI

    • Open Test Runner: npx cypress open or ./node_modules/.bin/cypress open
    • Folder Structure: /cypress/ with downloads/, fixtures/, support/, cypress.config.js
    • Test Types: E2E or Component; select browser (Chrome, Firefox, Electron).
    • Write Tests: Place .js spec files in configured folder.
    • Configure Spec Path: In cypress.config.js, set specPattern.
    • Run Tests: Click spec file in UI; see step-by-step execution, DOM snapshots, time-travel debugging.

    CLI Commands

    Task Command
    Open Cypress GUI npx cypress open
    Run all tests headless npx cypress run
    Run specific test file npx cypress run --spec "path/to/file.js"
    Run in headed mode npx cypress run --headed
    Run in Chrome npx cypress run --browser chrome
    Run in Edge npx cypress run --browser edge
    Run in Firefox npx cypress run --browser firefox

    🔍 Element Identification & CSS Selectors

    • Cypress supports CSS selectors (not XPath).
    • Inspect elements using browser DevTools.
    • Selector strategies:
    • #idName (ID)
    • .className (Class)
    • tag.class or tag#id (Tag + Class/ID)
    • [attribute="value"] (Attribute)
    • parent child (Hierarchy)
    • Validate selectors in DevTools: document.querySelector('selector')
    • Use Cypress Selector Playground for suggestions.
    • Locate elements: cy.get('css_selector')

    🧠 Cucumber BDD Integration with Cypress

    Why Use Cucumber BDD?

    • Gherkin syntax (Given-When-Then) for readable, collaborative test cases.
    • Stakeholders can review scenarios.

    Setup Steps

    1. Install Plugin:
      npm install --save-dev cypress-cucumber-preprocessor
    2. VS Code Extension:
      Install "Cucumber (Gherkin) Full Support".
    3. Create Feature File:
      Place .feature files in cypress/e2e/BDD/.
    4. Step Definitions:
      Create JS files in matching folders (e.g., BDD/ecommerce/ecommerceStepDef.js).

    Example Gherkin Syntax

    Feature: End-to-End E-Commerce Validation

  Scenario: E-commerce Product Delivery
     Given I am on E-commerce page
     When I log in to the application
     And I add items to cart
     And I validate the total price limit
     Then Select the country, submit, and verify Thank You

    Step Definitions Example

    import { Given, When, Then } from "@badeball/cypress-cucumber-preprocessor";

Given("I am on the e-commerce page", () => {
  // navigation code
});
When("I log in to the application", function () {
  // login code using this.data
});

    Data Sharing with Hooks

    import { Before } from "@badeball/cypress-cucumber-preprocessor";
Before(function () {
  cy.fixture("example").then((data) => {
     this.data = data;
  });
});
    • Use function () syntax for step definitions to access shared state via this.

    Cypress Config for Cucumber

    const { defineConfig } = require("cypress");
const browserify = require("@cypress/browserify-preprocessor");
const { addCucumberPreprocessorPlugin } = require("@badeball/cypress-cucumber-preprocessor");
const { preprendTransformerToOptions } = require("@badeball/cypress-cucumber-preprocessor/browserify");

async function setupNodeEvents(on, config) {
  await addCucumberPreprocessorPlugin(on, config);
  on("file:preprocessor", browserify(preprendTransformerToOptions(config, browserify.defaultOptions)));
  return config;
}

module.exports = defineConfig({
  e2e: {
     setupNodeEvents,
     specPattern: "cypress/e2e/BDD/*.feature"
  }
});

    🧪 Data-Driven Testing, Tags, and CLI Execution

    • Data Tables in Feature Files: gherkin When I login to application portal | username | password | | Rahul Shetty Academy | learning |
    • Access in Step Definitions: js When('I login to application portal', function (dataTable) { const username = dataTable.rawTable[1][0]; const password = dataTable.rawTable[1][1]; // login logic });
    • Use Scenario Outline for data-driven tests.
    • Tags:
      Add @smoke to scenarios, run with npx cypress run --env tags=@smoke.

    📊 Cucumber HTML Reports in Cypress

    Steps

    1. Enable JSON Output in package.json: json "cypress-cucumber-preprocessor": { "json": { "enabled": true, "output": "cypress/cucumber-reports/results.json" } }
    2. Install Cucumber JSON Formatter:
      Download and place binary in project root.
    3. Run Tests:
      npx cypress run --spec "cypress/e2e/BDD/yourFile.feature"
    4. Install HTML Reporter:
      npm install multiple-cucumber-html-reporter --save-dev
    5. Create Report Generator Script (generate-html-report.js): js const reporter = require("multiple-cucumber-html-reporter"); reporter.generate({ jsonDir: "cypress/cucumber-reports", reportPath: "cypress/cucumber-reports", metadata: { browser: { name: "chrome", version: "113" }, device: "Local test machine", platform: { name: "macOS", version: "11.2.3" }, }, customData: { title: "Run info", data: [ { label: "Project", value: "Rahul Shetty Academy Project" }, { label: "Release", value: "1.2.3" }, { label: "Execution Start Time", value: new Date().toLocaleString() }, ], }, });
    6. Generate HTML Report:
      node generate-html-report.js
    7. Open Report:
      cypress/cucumber-reports/index.html
