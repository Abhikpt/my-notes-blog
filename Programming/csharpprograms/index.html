    C# Basic Rules

    Naming Conventions:

    1. camelCase: For variables (e.g., customerName).
    2. PascalCase: For classes, structures, namespaces, fields, methods, and properties (e.g., CustomerDetails).
    3. IPascalCase: For interfaces (e.g., ICustomerName).
    4. _camelCase: For private fields (e.g., _accountNumber).

    Main Method:

    • Entry point of the program.
    • Must be static.

    System.Console.WriteLine():

    • System: Namespace in the Base Class Library (BCL).
    • Console: Predefined class inside the System namespace.
    • WriteLine(): Method defined in the Console class.

    Introduction to OOP

    Programming Model for Scalable Applications

    • Used in most popular languages such as Java, Python, JavaScript, C++, etc.
    • The goal of OOP is to group data and its operations as a single unit called an "Object".

    Class

    • A class is a blueprint for creating objects that encapsulate data and behaviors.
    • A class is a model of objects.
    • A class (a.k.a "type") represents the structure (list of fields and methods) of data you want to store in similar objects.
    • Objects are created based on a "Class".

    Example:

    class Car {
    string regNo;
    string carModel;
    int carYear;
}

    Key Points:

    • A class represents the structure of data you want to store in an object.
    • It is not a collection of objects.
    • Classes can have only two types of access modifiers: public and internal.

    Scenario: Imagine you are sitting at a table with two laptops, one Lenovo and one Dell: - You are an object of the Person class. - Lenovo and Dell are two objects of the Laptop class.

    Class Members:

    1. Fields
    2. Methods
    3. Constructors
    4. Properties
    5. Events
    6. Delegates

    Concepts of Class:

    1. Namespace: Organizes and groups related classes to avoid naming conflicts.
    2. Class Declaration: A blueprint for creating objects.
    3. Access Modifiers:
    4. public: Accessible anywhere.
    5. private: Accessible only within the class.
    6. protected: Accessible within the class and derived classes.
    7. Fields: Variables defined at the class level.
    8. Constants: Fixed values that cannot be modified.
    9. Constructor: Initializes fields or sets up the object.
    10. Properties: Provide controlled access to private fields.
    11. Events: Enable communication between objects.
    12. Methods: Perform operations or actions.
    13. Destructors: Cleanup when an object is destroyed.

    Sample Code:

    using System;

namespace OOPConceptsDemo
{
   public class MyClass
   {
      private string _name;
      public int Id;
      public const string Organization = "TechWorld";

      public string Name
      {
        get { return _name; }
        set { _name = value; }
      }

      public int Age { get; set; }

      public MyClass(int id, string name, int age)
      {
        Id = id;
        _name = name;
        Age = age;
      }

      public event Action OnDataUpdated;

      public void UpdateData(string newName, int newAge)
      {
        _name = newName;
        Age = newAge;
        OnDataUpdated?.Invoke();
      }

      public void DisplayInfo()
      {
        Console.WriteLine($"Id: {Id}, Name: {_name}, Age: {Age}, Organization: {Organization}");
      }

      ~MyClass()
      {
        Console.WriteLine("Object is being destroyed.");
      }
   }

   class Program
   {
      static void Main(string[] args)
      {
        MyClass person = new MyClass(1, "Alice", 25);
        person.OnDataUpdated += () => Console.WriteLine("Data has been updated!");
        person.DisplayInfo();
        person.UpdateData("Bob", 30);
        person.DisplayInfo();
      }
   }
}

    Objects

    • An object is a small unit (entity) in the program that represents a real-world person or thing.
    • A blueprint of a class.
    • Instance of a class.

    • Has behavior and properties.

    • Examples: You, Your laptop.

    • Any physical thing can be considered an object.
    • An object is an instance (example) of a "class".
    • Objects store a set of fields (details about the object).

    Methods

    • A method is a collection of statements to perform certain operations (processes or work), such as performing calculations, displaying output, or checking conditions.
    • A method should be a member (part) of a class.
    • Code statements are not allowed outside the class; they are allowed inside the method only.

    Example:

    class Car {
    int calculateEmi(int carPrice, int noOfMonths, int interestRate) {
        // Perform calculation here
        return emi;
    }
}

    Object & Class Association

    • Objects store fields.
    • Objects associate with all methods of their class, meaning objects can call methods of their class.
    • A class declares a list of fields and defines a list of methods.

    Creating a Class and Object

    Creating a Class

    Define the structure of the object.

    Creating an Object

    1. Creating a Reference Variable: csharp ClassName referenceVariable;

    2. Create Object and Store its Reference: csharp referenceVariableName = new ClassName();

    Key Points to Remember

    • An object is a programmatic representation of a person or thing.
    • All objects are created based on classes and stored in the 'heap'.
    • For each application execution, a new heap will be created (and only one).
    • All reference variables (local variables of methods) are stored in the stack. For each method call, a new stack will be created.
    • A method is a collection of statements to perform some operation or calculation.
    • A class supports two access modifiers: internal and public.
    • A class supports four modifiers: static, abstract, sealed, and partial.
    • Objects store actual data (group of fields) and can access methods of the class.
    • A reference variable stores the address of an (only one) object.

    Fields

    • Variables that are declared in the class and stored in the objects.
    • Fields are isolated for each object.

    Example:

    class Car {
    string regNo;
    string carModel;
    int carYear;
}

    Syntax of Field

    AccessModifier DataType FieldName;

    Access Modifiers of Fields

    • Access Modifier (a.k.a. "Access Specifier" or "Visibility Modifier") specifies the accessibility of fields, determining where the fields can be accessed.
    • They provide security for the fields.

    Static Fields

    • Static fields are stored outside the object.
    • Static fields are common to all objects of a class.

    Example:

    class BankAccount {
    long accountNumber;
    string accountHolderName;
    double currentBalance;
    static string bankName;
}

    Class Memory in Heap

    • Static Field: bankName: Bank of Dummyland

    Objects in Heap

    • Object 1:
    • accountNumber: 1001
    • accountHolderName: Scott
    • currentBalance: 5000
    • Object 2:
    • accountNumber: 1002
    • accountHolderName: Bob
    • currentBalance: 6000

    Instance Fields vs Static Fields

    Aspect Instance Fields Static Fields
    Storage Stored in Objects Stored in Class's memory
    Related to Represents data related to objects Represents common data for all objects
    Declaration Declared without static keyword Declared with static keyword
    Accessible with Accessible with object (reference var) Accessible with class name only
    Memory Allocation Allocated separately for each object Allocated once for the entire program

    Constant Fields

    • Constant fields are like static fields, common to all objects of the class.
    • The value of a constant field cannot be changed.
    • Constant fields are accessible with the class name (not with the object).
    • Constant fields are not stored in the object or memory; they are replaced with their value during compilation.
    • Constants must be initialized in-line with their declaration (with a literal value only).

    Syntax:

    AccessModifier const DataType FieldName = value;

    Readonly Fields

    • Readonly fields are like instance fields, stored in every object individually.
    • The value of a readonly field cannot be changed.
    • Readonly fields are accessible with a reference variable (object).
    • Readonly fields must be initialized either "in-line with declaration" or "in the constructor".

    Syntax:

    AccessModifier readonly DataType FieldName = value;

    Key Points to Remember

    • Fields are variables declared in the class but stored in objects.
    • Access modifiers of fields: private, protected, private protected, internal, protected internal, public.
    • Modifiers of fields: static, const, readonly.
    • Instance fields are individual for each object; static fields are common (one-time) for all objects.
    • Constants must be initialized along with the declaration; readonly fields must be initialized either "along with declaration" or in the "instance constructor".

    OOP Principles

    Encapsulation:

    • Protects important data inside a class.
    • Hides private or unwanted data from outside the class.

    Access Modifiers: Access modifiers manage how classes and class members are accessed.

    #### For Classes: 1. internal 2. public 3. private (only for nested classes)

    • private: Accessible only within the class.
    • public: Accessible from anywhere.
    • protected: Accessible within the class and derived classes.
    • internal: Accessible within the same assembly.
    • protected internal: Accessible within the same assembly or derived classes.
    • private protected: Accessible within the containing class or derived classes in the same assembly.

    Note:

    • For classes we canuse only internal, public, and private Access modifier.
    • private acees modifier use only for nested classes

    Best practices:

    1. Encapsulation: Use private methods to hide implementation details.
    2. Reusability: Use static or extension methods for utility functions.
    3. Simplicity: Avoid overusing modifiers like virtual unless necessary.
    4. Consistency: Use meaningful names and follow naming conventions (PascalCase).

    Collections in C

    • Collections in C# are a set of predefined classes available in the System.Collections namespace. These classes provide more capabilities and flexibility than traditional arrays.
    • Collections are nothing but groups of records that can be treated as one logical unit.

    Examples:

    • A Country Collection can contain items like CountryCode and CountryName.
    • A Product Collection might store ProductId and ProductName.
    • An Employee Collection could hold EmployeeId and EmployeeName.
    • A Book Collection might include ISBN and BookTitle.

    Key Features of Collections:

    • Dynamic Size: Collections can grow or shrink dynamically as needed.
    • Insert/Remove at Any Position: You can insert or remove elements from anywhere in the collection.
    • Rich Functionality: Collections provide built-in methods to store, retrieve, update, delete, search, and sort objects.
    • Efficient and Reliable: They are well-tested and optimized for performance.

    Why Use Collections Instead of Arrays?

    • Arrays have a fixed size, whereas collections can dynamically adjust.
    • Collections provide methods that make complex operations simpler.
    • Collections standardize the way objects are handled, promoting cleaner and more maintainable code.

    Common Operations:

    With collections, you can easily: - Store and retrieve multiple objects - Search through elements - Sort and filter data - Perform batch operations like removing or updating elements

    In simple terms, a collection in C# can be considered a more powerful and flexible form of array that is specifically designed to handle groups of objects efficiently.

    General Categories of Collections

    Collections are classified into 4 types.

    1. Indexed-Based Collection

    In indexed-based collections, an index is autogenerated while adding any element to the collection, such as arrays, lists, or ArrayLists. The index number can be used to identify the records.

    Example of Country Collection:

    Internal Index Country Code Country Name
    0 IND India
    1 AUT Austria
    2 BLR Belarus
    3 BTN Bhutan
    4 JPN Japan 
    Array[0] = "India";
List[1] = "AUT";

    2. Key-Value Pair Collections

    Key-value pair collections include Hashtable, Dictionary, and SortedList. In this type of collection, keys are used to identify elements instead of indexes.

    Example of Country Collection:

    Internal Index Country Code Country Name
    0 IND India
    1 AUT Austria
    2 BLR Belarus
    3 BTN Bhutan
    4 JPN Japan 
    Hashtable["IND"] = "India";

    3. Prioritized Collections

    Prioritized collections allow access to elements in a specific sequence. Examples include Stack and Queue.

    • Queue: First In First Out (FIFO)
    • Stack: Last In First Out (LIFO)

    4. Specialized Collections

    Specialized collections are designed for specific purposes. For example, a HybridDictionary starts as a list and then becomes a hashtable.

    Why Use a Dictionary Instead of an Array?

    Using a Dictionary<int, Employee> over a simple array of Employee objects offers several advantages:

    1. Key-based Access:
    2. A dictionary allows efficient access using a key.

    3. Example: csharp Employee emp = employees[2]; // Instantly get the employee with ID 2

    4. Handling Non-Sequential and Sparse Data:

    5. Dictionaries do not require contiguous or sequential keys, making them memory-efficient for sparse data.

    6. Flexibility in Modifying the Collection:

    7. Adding or removing entries in a dictionary is efficient and does not require shifting elements.

    8. Uniqueness of Keys:

    9. Ensures no two employees have the same ID, preventing data integrity issues.

    10. Performance:

    11. For large datasets, dictionaries offer significant performance advantages for lookups, additions, and deletions.

    Understanding Predicate and Delegate in C

    What is a Delegate?

    • A delegate is a type that represents references to methods with a specific signature.
    • It allows methods to be passed as parameters.

    Example:

    delegate void DisplayMessage(string message);

static void ShowMessage(string msg) {
    Console.WriteLine(msg);
}

DisplayMessage del = ShowMessage;
del("Hello, this is a delegate example!");

    What is a Predicate?

    • A Predicate<T> is a built-in generic delegate that represents a method returning a bool (i.e., it checks a condition).

    Example:

    static bool IsEven(int number) {
    return number % 2 == 0;
}

List<int> numbers = new List<int> { 1, 2, 3, 4, 5, 6 };
List<int> evenNumbers = numbers.FindAll(IsEven);
evenNumbers.ForEach(n => Console.WriteLine(n));

    Predicate Using Lambda Expression

    • Instead of a separate method, you can use a lambda expression for Predicate<T>:
    List<int> evenNumbers = numbers.FindAll(n => n % 2 == 0);

import java.util.*;

public class Main {
    public static void main(String[] args) {

       String str = "swiss";

        // Call the function to find the index
        int index = firstNonRepeatingIndex(str);

        if (index != -1) {
            System.out.println("First non-repeating character is at index: " + index);
        } else {
            System.out.println("No unique character found.");
        }
    }

    public static int firstNonRepeatingIndex(String str) {
        // Step 1: Count the occurrences of each character
        HashMap<Character, Integer> charCount = new HashMap<>();

        // Traverse the string and populate the map with character counts
        for (char c : str.toCharArray()) {
            charCount.put(c, charCount.getOrDefault(c, 0) + 1);
        }

        // Step 2: Find the first character that appears only once
        for (int i = 0; i < str.length(); i++) {
            if (charCount.get(str.charAt(i)) == 1) {
                return i; // Return the index of the first unique character
            }
        }

        return -1; // Return -1 if no unique character is found
  }
}

    1. Reverse an Array:

    Algorithm: 1. Step1: Create two variables named startIndex and endIndex and initialize values with 0 and (n-1) respectively. (n is the length of the array). 2. Step2: Swap the values of startIndex with endIndex and increment the value of startIndex by 1 (means +1) and decrement the value of endIndex by 1 (means -1). 3. Step3: Repeat Step2 until the startIndex value is less than the endIndex value. 4. Step4: Print the array as a reversed array.

    using System;
using System.Collections.Generic;

using System.Linq;
using System.Text.RegularExpressions;

namespace HelloWorld
{
  public class Program
  {
    public static void Main(string[] args)
    {
      int[]   arry = {1,3,4,6,2,5,12}; 

      SwapElements(arry, 0, arry.Length-1); 

      Console.WriteLine(string.Join(", ", arry));      
    }  

    static void SwapElements(int[] arr, int startIndex, int endIndex)
        {
            while (startIndex < endIndex)
            {
                int temp = arr[startIndex];
                arr[startIndex] = arr[endIndex];
                arr[endIndex] = temp;
                startIndex++;
                endIndex--;
            }
        }
  }
}

    1. C# program to find two prime numbers whose sum equals the given prime number

    • Check if the given number is prime. • Find two prime numbers (p1 and p2) such that: • p1+ p2 = given Prime Number • Print the pair of prime numbers.

    Csharp:

    using System;

class PrimeSumFinder
{
    // Function to check if a number is prime
    static bool IsPrime(int num)
    {
        if (num < 2) return false;
        for (int i = 2; i * i <= num; i++)
        {
            if (num % i == 0) return false;
        }
        return true;
    }

    // Function to find two prime numbers whose sum equals the given prime
    static void FindPrimeSum(int primeNumber)
    {
        if (!IsPrime(primeNumber))
        {
            Console.WriteLine($"{primeNumber} is not a prime number.");
            return;
        }

        bool found = false;

        for (int i = 2; i <= primeNumber / 2; i++)
        {
            int j = primeNumber - i;

            if (IsPrime(i) && IsPrime(j))
            {
                Console.WriteLine($"Prime numbers: {i} + {j} = {primeNumber}");
                found = true;
            }
        }

        if (!found)
        {
            Console.WriteLine($"No two prime numbers sum to {primeNumber}.");
        }
    }

    static void Main()
    {
        Console.Write("Enter a prime number: ");
        int primeNumber = int.Parse(Console.ReadLine());

        FindPrimeSum(primeNumber);
    }
}
