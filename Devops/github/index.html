    🧠 Git & GitHub Notes

    📁 What is Git?

    Git is a: - Free - Open-source - Distributed - Version Control System (VCS) - Designed to handle everything from small to large projects with speed and efficiency. - Git allows you to have local repositories.

    Git commands:

    🔹 1. Branch Basics

    • View branches
    git branch        # local branches
git branch -r     # remote branches
git branch -a     # all branches
    • Create branch
    git checkout -b feature/uat3
    • Switch branch
    git checkout develop
    • Rename branch
    git branch -m old-name new-name

    🔹 2. Staging, Changes & Commits

    • Changes → modified but not yet staged.

    • Staged changes → added via git add, waiting for commit.

    • Commit changes:

    git commit -m "message"
    • Unstage files:
    git reset HEAD <file>
    • Check staged/unstaged:
    git status

    🔹 3. See Changed Files (diffs)

    3.1 Changed file names only - Compare working dir vs last commit:

    git diff --name-only
    • Compare two commits:
    git diff --name-only <commit1> <commit2>
    • Compare staged changes:
    git diff --name-only --cached
    • Compare last commit:
    git diff --name-only HEAD~1 HEAD
    • Show status (added/modified/deleted):
    git diff --name-status

    3.2 Changes in a specific file

    • Working directory:
    git diff <file-path>
    • Staged changes:
    git diff --cached <file-path>
    • Between commits:
    git diff <commit1> <commit2> -- <file-path>
    • File name only:
    git diff --name-only -- <file-path>

    🔹 4. Stash

    Temporarily saves your changes without committing.

    • Save changes:
    git stash
    • Apply stashed changes:
    git stash pop
    • Apply later (keep stash):
    git stash apply
    • View stashes:
    git stash list

    👉 You can stash in any branch, then apply in another branch.

    🔹 5. Push

    • Push current branch
    git push

    ✅ Only current branch is pushed (0% chance others get pushed).

    Push specific branch

    git push origin feature/login

    -Push all branches (⚠ risky)

    git push --all
    • Check before push
    git push --dry-run

    🔹 6. Revert, Reset & Push

    • Revert (safe, shared branches)
    git revert <commit-id>
git push origin <branch>
    • If branch is behind remote
    git pull --rebase origin <branch>
git push origin <branch>
    • Reset (rewrite history, risky)
    git reset --hard <commit-id>
git push origin branch-name --force

    🔹 7. Remove Branch & Fetch from Remote

    • Switch to another branch:
    git checkout main
    • Delete local branch:
    git branch -D <branch>
    • Fetch remote:
    git fetch origin
    • Recreate from remote:
    git checkout -b <branch> origin/<branch>

    🔹 8. Compare Branches

    • Full diff:
    git diff staging origin/develop
    • File names only:
    git diff --name-only staging origin/develop
    • Summary:
    git diff --stat staging origin/develop
    • Commits in staging but not develop:
    git log origin/develop..staging --oneline
    • Commits in develop but not staging:
    git log staging..origin/develop --oneline

    🔹 9. Fix “Your branch and 'origin/branch' have diverged”

    • Merge (keep both histories)
    git fetch origin
git checkout <branch>
git merge origin/<branch>
git push origin <branch>
    • Rebase (clean history)
    git fetch origin
git checkout <branch>
git rebase origin/<branch>
git push origin <branch> --force-with-lease
    • Reset (discard local commits)
    git fetch origin
git checkout <branch>
git reset --hard origin/<branch>

    🔹 10. Merge vs Rebase

    • Merge
    git merge develop

    Keeps history (adds merge commit). Safe for teamwork.

    • Rebase
    git rebase develop

    Replays commits on new base. Cleaner history, risky if branch is already pushed.

    🔹 11. Conflicts

    • During merge/rebase, Git stops at conflicts.
    git status   # shows conflicts
git add <file>
git merge --continue   # or git rebase --continue
    • Abort rebase:
    git rebase --abort

    🔹 12. Git Config

    • Check config
    git config --list
    • Set global username/email
    git config --global user.name "Your Name"
git config --global user.email "you@example.com"
    • Set per-repo
    git config user.name "Your Name"
git config user.email "you@example.com"

    🔹 13. Delete Files

    • Delete file + folder:
    git rm -r foldername
git commit -m "remove folder"
git push

    🔹 14. History

    • View commit history:
    git log --oneline --graph --decorate --all
    • Show details:
    git show <commit-id>

    🔹 15. Sync with Remote

    • Fetch updates
    git fetch origin
    • Merge develop into your branch
    git checkout fixes
git merge origin/develop
    • Rebase instead
    git checkout fixes
git rebase origin/develop

    🔹 16. Rebase Interactive

    git rebase -i HEAD~3
    • Options:
    pick → keep
squash → combine
edit → modify
drop → remove

    🔹 17. Undo Push (Remote)

    • If safe (personal branch)
    git reset --hard <commit-id>
git push origin branch --force
    • If shared branch
    git revert <commit-id>
git push origin branch

    ✅ Golden Rules

    • Use merge for team branches (safe).
    • Use rebase/reset only for your own branch before pushing.
    • Use revert to safely undo in shared repos.
    • Always git pull --rebase before pushing if behind.

    ☁️ What is GitHub?

    • GitHub is a company that offers:
    • Cloud Git repositories
    • Services to manage and collaborate on code
    • GitHub hosts your Git repositories in the cloud, enabling remote collaboration and workflow automation.

    🛠️ Steps to Initialize Git in a Local Folder and Push to GitHub

    1. Create a Repository on GitHub
    2. Copy the HTTPS path of the repo
      Example:
      https://github.com/Abhikpt/DockerPractice.git
    3. Run the following commands in your terminal:
    git init
git add .
git commit -m "first file"
git remote add origin https://github.com/Abhikpt/DockerPractice.git
git push origin master --force

    Working with SSH key:

    It is an secure Authentication methodused to connect youer local maching like git bash to remote services like GitHub, GitLab, or Bitbucket.

    • You can access and write data in repositories on GitHub using SSH (Secure Shell Protocol).
    • When you connect via SSH, you authenticate using a private key file on your local machine.

    🔐 Step 1: Generate an SSH key 1. Open Git Bash/ Git CMD (Search for it in the Start menu). 2. Run this command to create a new key:

    ssh-keygen -t ed25519 -C "your_email@example.com"
    1. Replace "your_email@example.com" with your actual email (used for GitHub, GitLab, etc.).
    2. If ed25519 doesn’t work, try rsa with:
    ssh-keygen -t rsa -b 4096 -C "your_email@example.com"
    1. When prompted:
    Enter file in which to save the key (/c/Users/YourName/.ssh/id_ed25519):
Press Enter to accept the default.
    1. Enter a passphrase (optional, for security), or just press Enter to skip.

    🧠 Step 2: Start ssh-agent and add the key 1. In Git Bash, run:

    eval "$(ssh-agent -s)"
    1. Then add your SSH key to the agent:
    ssh-add ~/.ssh/id_ed25519
    1. You should see a confirmation like:
    Identity added: /c/Users/YourName/.ssh/id_ed25519

    📋 Step 3: Copy your public key To copy the public key:

    clip < ~/.ssh/id_ed25519.pub

    This copies your SSH public key to the clipboard.

    ☁️ Step 4: Add your key to GitHub / GitLab / Bitbucket - GitHub: https://github.com/settings/keys - GitLab: https://gitlab.com/profile/keys - Bitbucket: https://bitbucket.org/account/settings/ssh-keys/

    Click New SSH Key, give it a name, paste your key in, and save.

    🔁 Step 5: Test the connection

    • To test GitHub, run:
    ssh -T git@github.com
    • Expected response:
    Hi yourusername! You've successfully authenticated, but GitHub does not provide shell access.

    how to clone an private repository:

    1. Using HTTPS with Personal Access Token (PAT)

    If you're using GitHub (similar steps for GitLab, Bitbucket):

    🔹 Steps: a. Go to the repository page. b. Click on "Code" → Select HTTPS → Copy the URL. c.Run:

    git clone https://github.com/username/repo-name.git

    d. When prompted:

    • Username → Enter your GitHub username.
    • Password → Enter your Personal Access Token (PAT) (not your GitHub password).

    e. GitHub no longer supports password authentication for Git over HTTPS. You must use a token.

    🔹 Generate a PAT:
GitHub: https://github.com/settings/tokens
GitLab: https://gitlab.com/-/profile/personal_access_tokens

    2. Using SSH (Recommended for frequent access)

    a. Generate SSH Key (if not done already):

    ssh-keygen -t ed25519 -C "your_email@example.com"

    b. Add SSH key to your GitHub/GitLab account:

    c. Copy your key:

    cat ~/.ssh/id_ed25519.pub

    d. Add it to:
    GitHub → Settings → SSH and GPG Keys → New SSH key GitLab → Preferences → SSH Keys

    e. Clone using SSH:

    git clone git@github.com:username/repo-name.git

    3. Using Git Credential Manager (for Windows users)

    Git Credential Manager stores your credentials securely so you don’t need to re-enter every time.

    git config --global credential.helper manager-core

    Then, cloning using HTTPS will trigger a UI prompt for login.
