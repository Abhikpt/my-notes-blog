    1. 🔗 Azure DevOps

    Azure covers a wide range of services — from hosting web apps and APIs to managing databases, CI/CD pipelines, machine learning, virtual machines, and more.

    Azure DevOps is a powerful platform for managing the entire software development lifecycle — including version control (Git), CI/CD pipelines, project tracking, testing, and artifact management.

    🔧 Core Services in Azure DevOps:

    Service Description
    Azure Boards Work item tracking (Agile, Scrum, Kanban).
    Azure Repos Git repositories for source code.
    Azure Pipelines Build and release pipelines (CI/CD).
    Azure Test Plans Manual and exploratory testing tools.
    Azure Artifacts Package management (NuGet, npm, Maven, etc.).

    🗂️ Azure DevOps Work Process (for Boards)

    Choose a process template to define how teams interact within the Azure DevOps framework:

    Template Description
    Basic Simplest model using Issues, Tasks, and Epics.
    Agile Supports Agile planning and tracks dev/test separately.
    Scrum Track PBIs and bugs on Kanban, break into tasks on taskboard.
    CMMI Supports formal change management and work tracking.

    📚 Azure Repos: Version Control

    Features:

    • Track changes in code
    • Make copies when adding/editing
    • Maintain code history

    Types of Version Control:

    1. Git (Distributed)

    • Free, open-source.
    • Works across Windows, macOS, and Linux.

    2. TFVC (Team Foundation Version Control) [Centralized]

    Create Azure repo:

    Azure Repos is a set of version control tools provided by Azure DevOps.

    🚀 Getting Started: - Click "New Repository" to create one. - Initialize the repository. - Create a branch for the repo to manage changes separately.

    Azure Pipelines:

    Build pipeline: • these pipelines jobs clone the code from assigned repositories and build the project based on instruction provided in yaml file. • Typically, we use build pipeline to publish artifacts of the project • Based on instruction we can build any kind of project like .net, JavaScript, angular etc.

    Release Pipeline: • These pipelines generally used to deploy the build artifacts into agent Machines.

    Create Release: • This component helps us to build end to end pipeline (connecting build and release pipeline) For CI/CD implementation.

    Azure Test Plans:

    It is a service in Azure DevOps used for manual testing, exploratory testing, and user acceptance testing (UAT). It helps teams plan, track, and manage testing efforts across the DevOps lifecycle.

    Advance Features:

    ✅ Test Configurations: Run the same test on different environments (e.g., OS, browsers).

    🔗 Work Item Integration: Link test cases to requirements and bugs.

    📈 Reporting & Analytics: Use built-in Power BI integrations for test analytics.

    🧪 Automated Test Integration: You can link automated tests from pipelines to test plans (e.g., via .runsettings or TestCase attributes in code).

    Create Azure Tests:

    1. Create a Test Plan

    Go to Azure DevOps > Test Plans.

    1. Click + New Test Plan.

    2. Add Test Suites

      • Static Suite: Manually add test cases.

      • Requirement-based Suite: Linked to backlog items (e.g., user stories).

      • Query-based Suite: Dynamically pulls test cases from a work item query.

    3. Create Test Cases

      • Add steps with expected results.

      • Attach screenshots, files, or links if needed.

    4. Run Tests

      • Click Run for web application or use the Test Runner.

      • Mark each step as pass/fail during execution.

      • Automatically create bugs when a step fails.

    5. Track Results

      • View Run summary, including test outcomes and execution time.

      • Use dashboards and reports to analyze quality

    Different way of deploying the Web Application on Azure

    1. Deploying the Web app using Azure App service

    I am going to use the command window / cloud cell here

    1. Define the web app name
    webappname="DevOpsSolution"
    1. Create an App service plan in S1 tier
    az appservice plan create --name $webappname --resource-group learn-50ccdcdf-3e51-4ea3-8084-44bb6a213df2 --sku S1
    1. Create the web app resources using the App service plan in same resource group
    az webapp create --name $webappname --resource-group learn-35e59348-a05b-4105-9fd0-88fab98e170d --plan $webappname
    1. Set the deployment branch to main in the appsettings configuratioon.
    az webapp config appsettings set --name $webappname --resource-group learn-35e59348-a05b-4105-9fd0-88fab98e170d --setting DEPLOYMENT_BRANCH=main
    1. Set the deployment credentials
    az webapp deployment user set --user-name UsrXYZ --password Pass@xyz
    1. Configure the web app to accept deployments from local git and display the git deployment URL: 
    echo Git deployment URL :$(az webapp deployment source config-local-git --name $webappname --resource-group learn-35e59348-a05b-4105-9fd0-88fab98e170d --query url --output tsv)

    or 

    echo Git deployment https://github.com/Abhikpt/DevOpsSolution :$(az webapp deployment source config-local-git --name $webappname --resource-group learn-35e59348-a05b-4105-9fd0-88fab98e170d --query url --output tsv)
    1. Display the web app URL
    echo Web app URL: http://$webappname.azurewebsite.net

    1. Now go to you local command terminal

    2. add the Remote URL (point 06) to local repository

    git remote add azure-prod GIT_DEPLOYMENT_URL
    • push the local default branch main to azure-prod
    git push azure-prod main

    • wait till get get success response of deployment

    • Open the Web App URL (point 07) and check app has been built and deployed.
