    📒 CI/CD for Playwright with C# and NUnit (GitHub Actions)

    ✅ Project Structure (Relevant for CI)

    /TestResults/               <-- NUnit test result (.trx)
/Screenshot/                <-- Screenshots (e.g., failed tests)
/Resources/                 <-- HTML reports (Playwright)
/Logs/                      <-- Optional: custom log files
/bin/Release/net8.0/        <-- Compiled binaries and playwright.ps1

    🚀 GitHub Actions Workflow: playwright.yml

    📁 Location:

    .github/workflows/playwright.yml

    📋 Trigger:

    Runs on every push to the main branch:

    on:
  push:
    branches: [ main ]

    🛠 Full Example Workflow with Explanation

    name: Playwright Test Workflow

on:
  push:
    branches:
      - project_ql

jobs:
  build:
    runs-on: ubuntu-latest

    steps:
      # Check out the code
      - name: Checkout repository
        uses: actions/checkout@v4

      # Set up .NET SDK
      - name: Set up .NET
        uses: actions/setup-dotnet@v4
        with:
          dotnet-version: '8.0'

      # Restore dependencies
      - name: Restore dependencies
        run: dotnet restore

      # Build project
      - name: Build project
        run: dotnet build --configuration Release --no-restore

      # adding this steps to debug the correct path
      - name: List Playwright script path
        run: ls -R bin/

      - name: Install Playwright Browsers
        run: pwsh bin/Release/net8.0/playwright.ps1 install  # adjust net version

       # 👉 Add this step to run tests with xvfb (for headed mode)
      - name: Run Playwright Tests
        run: xvfb-run -a dotnet test --configuration Release --no-build --logger "trx;LogFileName=test-results.trx"

      # Upload artifacts
      - name: Upload test-logs
        if: always()
        uses: actions/upload-artifact@v4
        with:
          name: test-logs
          path: |
            TestResults/
            Logs/ 
            Screenshots/
            Resources/
            bin/Debug/net8.0/playwright-report/
  download_artifacts:
    needs: build  # Ensure this job runs after the 'build' job
    runs-on: ubuntu-latest

    steps:
      # Download uploaded artifacts
      - name: Download test-logs artifact
        uses: actions/download-artifact@v4
        with:
          name: test-logs
          path: ./downloaded-artifacts

    🧾 Workflow Step Breakdown

    ✅ Step 1: Checkout Code

    - name: Checkout code
  uses: actions/checkout@v3
    • Pulls the code from your GitHub repository into the runner machine.

    ✅ Step 2: Setup .NET SDK

    - name: Setup .NET
  uses: actions/setup-dotnet@v3
  with:
    dotnet-version: '8.0'
    • Installs the .NET 8 SDK so we can build and test our C# Playwright project.

    ✅ Step 3: Restore NuGet Packages

    - name: Restore dependencies
  run: dotnet restore
    • Restores all dependencies defined in your .csproj files using NuGet.

    ✅ Step 4: Build the Project

    - name: Build project
  run: dotnet build --configuration Release --no-restore
    • Compiles the code in Release mode.
    • --no-restore skips restoring packages again (already done in the previous step).

    ✅ Step 5: Install Playwright Browsers

    - name: Install Playwright Browsers
  run: pwsh bin/Release/net8.0/playwright.ps1 install
    • Installs the required browsers (Chromium, Firefox, WebKit) via Playwright.
    • This script is auto-generated after building the project.

    ✅ Step 6: Run Tests (With xvfb for UI Support)

    - name: Run Playwright Tests (headful mode with xvfb)
  run: xvfb-run -a dotnet test --configuration Release --no-build --logger "trx;LogFileName=test-results.trx"
    • Runs NUnit tests.
    • xvfb-run is used to simulate a display environment for UI browsers. ie. headed mode of browser.
    • --logger "trx" generates a test result file.

    ✅ Step 7: Upload Test Artifacts

    - name: Upload test artifacts
  if: always()
  uses: actions/upload-artifact@v3
  with:
    name: test-results
    path: |
      TestResults/
      Screenshot/
      Resources/
      Logs/
    • Uploads results (screenshots, reports, logs) for review, even if tests fail.
    • You can later download these artifacts from the GitHub Actions UI.

    ✅ Step 8: Download Artifacts (Optional Step)

    - name: Download test artifacts
  uses: actions/download-artifact@v3
  with:
    name: test-results
    • Allows retrieval of uploaded test artifacts in subsequent jobs or local machine.
    • Useful for report parsing, publishing, or retention.

    🧠 Summary of Tools Used

    Tool Purpose
    dotnet CLI Build, restore, test C# projects
    playwright.ps1 install Installs browser dependencies
    xvfb-run Provides virtual display for UI browser runs
    upload-artifact Saves screenshots, logs, test results for download
    download-artifact Retrieves uploaded files for further use in pipeline or local

    💡 Tips

    • Use if: always() when uploading artifacts — ensures logs/screenshots are saved even on test failure.
    • Use xvfb-run only when running Playwright in headed mode (browser UI). Otherwise, set Headless = true in test code.
    • Always confirm your output folders (e.g., Screenshot/, Resources/) exist before uploading them.
    • Download artifacts in separate jobs if you plan to analyze or publish reports further.
