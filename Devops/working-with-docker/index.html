    Docker & Test Automation Notes

    Introduction to Docker

    • Free and open source
    • Virtual environment for all dependencies
    • Prevents failure due to upgrades (Java, Chrome, Maven, etc.)
    • Allows creation of Docker images containing necessary software

    Workflow: Click to run ➝ One or multiple containers start ➝ Tests execute ➝ Containers return to idle

    Why need?

    • Due to Test Dependencies.
    • When creating test automation, the following dependencies are often required:
    • Java
    • Maven
    • Test script
    • Firefox browser
    • Chrome browser
    • ChromeDriver
    • Your code
    • Directory structure
    • Test resources (data files, test cases, etc.)

    Create an docker image

    To create a Docker image, you generally need a Dockerfile that contains a set of instructions Docker uses to build the image. - Create a Dockerfile

    • Build the image: By Running this command in the terminal where your Dockerfile is located.
    docker build -t myapp:latest .

    myapp is the name of the image.
    . indicates the current directory (where Dockerfile is present).

    • Verify the images by running commands
    docker images

    Dockerfile Commands

    Command Description
    FROM image Sets the base image to use
    ADD host-files container-files Copies files from host directory to container
    RUN command Executes a command (e.g. install pkgs)
    ENV var value Sets an environment variable
    WORKDIR path Set working directory inside the container
    EXPOSE port Informs Docker to open the specified port
    ENTRYPOINT command Defines the default executable
    # Used for comments in the Dockerfile

    Working With Docker Container:

    Creating docker container

    A container is a running instance of a Docker image. To create one, you use the docker run command.

    Syntax:
    docker run [OPTIONS] IMAGE [COMMAND] [ARG...]

    Options:
    -d -> Run in background
    -i -> Attach input
    -t -> Attach output
    --name NAME -> Name container
    --entrypoint=/bin/bash -> Override entrypoint
    -p 8080:8080 -> Map ports
    -v /host:/container -> Volume mapping

    Example:

    # 1.Runs the container in detached mode
docker run -d imageName

# 2.Runs the ubuntu container in interactive mode with terminal access
docker run -it ubuntu 

# 3.Runs the container with custom entrypoint (e.g., bash)
docker run -it --entrypoint=/bin/bash imageName

# 4.Run a container with mounted volume
docker run -d -v /host/path:/container/path myimage

# 5.Remove container
docker rm containerName

    Port Mapping in Docker

    Port Mapping is a technique used to allow communication between devices or applications by mapping ports on a host machine to specific ports on another machine or a containerized environment. It's commonly used in networking, containerization (e.g., Docker), and application hosting.

    • If multiple applications are running on a machine, then to access them from external applications/machines we use port mapping.
    • At a time two applications cannot be assigned the same port. We have to stop one application to assign the port to another.

    Why is Port Mapping Needed?

    1. External Access: Makes an application or service running on a specific port inside a container or a private network accessible externally.
    2. Port Collision Avoidance: Helps to avoid conflicts when multiple services use the same port.
    3. Control and Security: Restricts access to specific ports and provides flexibility in managing traffic.

    Docker Command for Port Mapping

    docker run -p hostPort:containerPort image
    • Port 80 is the default port.

    Examples:

    docker run -p 80:80 vindocker/jmserver
docker run -p 4444:80 mongo
    • Docker Multi-Container Flow (with Network and Host Access)
                    ┌────────────┐
                │ Machine A  │
                └─────┬──────┘
                      │
               10.11.12.13
                      │
                      ▼
            ┌────────────────────┐
            │      Docker        │
            ├────────┬───────────┤
            │ Port 80│ Port 90   │
            ├────────┴───────────┤
            │                    │
  ┌───────────────┐   ┌────────────────┐
  │ Container/vm 1│   │ Container/vm 2 │

    docker run -p 80:80 vindocker/jenkins
docker run -p 80:9023 vindocker/Ubuntu
docker run -p 90:80 SeleniumGrid

    Docker Project Setup and Usage

    Working with Docker in My Project

    Step-by-Step Guide:

    1. Install Docker on your system.
    2. Navigate to your project directory and create a docker-compose.yml file. This file defines and supports running your application in Docker.

    To Run It:

    1. docker-compose build ➝ Builds the application as an image that will run in a container.

    2. docker images ➝ Lists the created images.

    3. docker-compose up ➝ Runs the application based on the docker-compose.yml file.

    4. Open the localhost URL as configured in your Docker setup to access the application.

    Docker in My API Project

    docker-compose.yml:

    # version: '3.4' # not required in new version
services:
  ea_api:
    image: ea_api
    container_name: eaapi
    build:
      context: .
      dockerfile: GraphQL.NET/Dockerfile
    restart: on-failure
    ports:
      - 5001:8000
    networks:
      - ea_network

networks:
  ea_network:

    Dockerfile:

    FROM mcr.microsoft.com/dotnet/aspnet:6.0 AS base
WORKDIR /app
EXPOSE 80
EXPOSE 443

FROM mcr.microsoft.com/dotnet/sdk:6.0 AS build
WORKDIR /src
COPY ["GraphQL.NET/GraphQLProductApp.csproj", "GraphQL.NET/"]
RUN dotnet restore "GraphQL.NET/GraphQLProductApp.csproj"
COPY . .
WORKDIR "/src/GraphQL.NET"
RUN dotnet build "GraphQLProductApp.csproj" -c Release -o /app/build

FROM build AS publish
RUN dotnet publish "GraphQLProductApp.csproj" -c Release -o /app/publish /p:UseAppHost=false

FROM base AS final
ENV ASPNETCORE_ENVIRONMENT=Development
ENV ASPNETCORE_URLS=http://*:8000
EXPOSE 8000
WORKDIR /app
COPY --from=publish /app/publish .
ENTRYPOINT ["dotnet", "GraphQLProductApp.dll"]

    Command Description
    docker ps List all running Docker containers.

    docker run <image_name> Run a container from a Docker image.

    Building Docker Images:

    • docker build -t <image_name> <path_to_dockerfile> – Build a Docker image from a Dockerfile.

    Docker Volumes:

    • docker volume create <volume_name> – Create a Docker volume.
    • docker volume ls – List all Docker volumes.
    • docker volume rm <volume_name> – Remove a Docker volume.

    Docker Networks:

    • docker network ls – List all Docker networks.
    • docker network create <network_name> – Create a custom Docker network.
    • docker network connect <network_name> <container_name> – Connect a container to a network.

    Copying Files:

    • docker cp <container_id>:<container_path> <host_path> – Copy from container to host.
    • docker cp <host_path> <container_id>:<container_path> – Copy from host to container.

    Docker-Compose

    • docker-compose is a tool for defining and managing multi-container Docker applications.
    • Uses docker-compose.yml to configure services, networks, and volumes.
    • Simplifies running applications requiring multiple containers.

    Basic Workflow with docker-compose:

    1. Define your services in docker-compose.yml.
    2. Run docker-compose up to start services.
    3. Run docker-compose down to stop and clean up.

    Sample docker-compose.yml Structure:

    version: '3'
services:
  web:
    image: nginx:latest
    ports:
      - "8080:80"
    volumes:
      - ./html:/usr/share/nginx/html

  db:
    image: mysql:5.7
    environment:
      MYSQL_ROOT_PASSWORD: example
    volumes:
      - db_data:/var/lib/mysql

volumes:
  db_data:
